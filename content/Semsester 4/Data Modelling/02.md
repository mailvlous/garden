## Fact Table

Fact table have some foreign key from dimension table(primary key)

## Star Schema

### Kelebihan:

* kecepatan(denormalisasi meminimalkan jumlah join), kemudahan, efisiensi(struktur paling optimal nuntuk navigasi data multidimensional)

### Kekurangan:

* redundansi data, integritas data(perubahan memerlukan update di banyak baris)

## Snowflake Shema

### Kelebihan

* efisiensi storage(normalisasi menghilangkan redundansi data), integrasi data(perubahan hanya perlu dilakukan di satu tempat)

### Kekurangan

* performa query, kompleksitas

## 

>star untuk performa analitik responsif, snowflake untuk efisiensi jika kritis

>tidak boleh circular, hierarki yg ada

>surrogate

>we can have sub fact table



## ETL

### Extract

* mengambil data mentah
* identifikasi data baru

### Transform

* data cleaning, standarisasi format
* pembuatan surrogate keys untuk table dimensi
* agregasi awal dan penangana SCD

### Load

* memuat data ke table dimensi
* memuat data ke table fact untuk menjaga integritas
* incremental load
